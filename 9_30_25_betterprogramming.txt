To make your SvelteKit 2 projects better, focus on writing modular code by breaking logic into smaller, single-purpose functions, using TypeScript to define clear data shapes, organizing exports with barrel files for cleaner imports, leveraging Svelte's reactive stores for state management, and understanding the event loop for asynchronous operations.

## Modular Functions & TypeScript Methods
Instead of writing large, monolithic functions, break them down into smaller, reusable, and type-safe pieces. This makes your code easier to read, test, and maintain.

Less Effective: A single, large function

TypeScript

// src/routes/dashboard/+page.server.ts
import type { PageServerLoad } from './$types';

export const load: PageServerLoad = async ({ fetch }) => {
	// Fetching user data
	const userRes = await fetch('/api/user');
	const userData = await userRes.json();
	const userName = `${userData.firstName} ${userData.lastName}`;

	// Fetching user's posts
	const postsRes = await fetch(`/api/posts?userId=${userData.id}`);
	const postsData = await postsRes.json();
	const activePosts = postsData.filter((post: any) => post.status === 'active');
	const postTitles = activePosts.map((post: any) => post.title.toUpperCase());

	return {
		userName,
		postTitles,
	};
};
Better: Modular, type-safe functions
First, define your types to ensure data consistency.

TypeScript

// src/lib/types.ts
export interface User {
  id: string;
  firstName: string;
  lastName:string;
}

export interface Post {
  userId: string;
  title: string;
  status: 'active' | 'draft';
}
Next, create modular service functions to handle specific tasks.

TypeScript

// src/lib/services/userService.ts
import type { User } from '$lib/types';

// This function only handles fetching and formatting the user.
export async function getUser(fetch: Function): Promise<User> {
	const response = await fetch('/api/user');
	if (!response.ok) throw new Error('Failed to fetch user');
	return response.json();
}
TypeScript

// src/lib/services/postService.ts
import type { Post } from '$lib/types';

// This function handles fetching and processing posts.
export async function getActivePostTitles(userId: string, fetch: Function): Promise<string[]> {
	const response = await fetch(`/api/posts?userId=${userId}`);
	if (!response.ok) throw new Error('Failed to fetch posts');
	const posts: Post[] = await response.json();
	
	return posts
		.filter(post => post.status === 'active')
		.map(post => post.title.toUpperCase());
}
Finally, compose them in your load function, which is now much cleaner. ✨

TypeScript

// src/routes/dashboard/+page.server.ts
import type { PageServerLoad } from './$types';
import { getUser } from '$lib/services/userService';
import { getActivePostTitles } from '$lib/services/postService';

export const load: PageServerLoad = async ({ fetch }) => {
	const user = await getUser(fetch);
	const postTitles = await getActivePostTitles(user.id, fetch);

	return {
		userName: `${user.firstName} ${user.lastName}`,
		postTitles,
	};
};
## Barrel Files for Organization
A barrel file (index.ts) is a single file in a directory that exports all the modules from that directory. This simplifies your import statements significantly.

Less Effective: Multiple import lines

TypeScript

import { getUser } from '$lib/services/userService';
import { getActivePostTitles } from '$lib/services/postService';
Better: Using a barrel file
Create a file at src/lib/services/index.ts.

TypeScript

// src/lib/services/index.ts
export * from './userService';
export * from './postService';
Now your import statement becomes a single, clean line.

TypeScript

import { getUser, getActivePostTitles } from '$lib/services';
## Svelte Stores for State Management
Stores are Svelte's built-in solution for managing reactive state that needs to be shared across multiple components. They are far more efficient and less error-prone than passing props down through many layers or using the Context API for everything.

Less Effective: Prop drilling
Passing data through components that don't need it is inefficient.

Svelte

<script>
	import Parent from './Parent.svelte';
	let user = { name: 'Jane' };
</script>
<Parent {user} />

<script>
	import Child from './Child.svelte';
	export let user;
</script>
<Child {user} />

<script>
	export let user;
</script>
<h1>Hello, {user.name}</h1>
Better: Using a writable store
Create a store to hold the state.

TypeScript

// src/lib/stores/userStore.ts
import { writable } from 'svelte/store';
import type { User } from '$lib/types';

export const user = writable<User | null>(null);
Any component can now subscribe to this store and react to its changes without prop drilling.

Svelte

<script>
    import { user } from '$lib/stores/userStore';

    // Set the user data from anywhere, perhaps in a root layout load function
    // For this example, we'll set it here.
    user.set({ id: '123', firstName: 'Jane', lastName: 'Doe' });

    // The '$' prefix provides auto-subscription
</script>

{#if $user}
    <h1>Hello, {$user.firstName}</h1>
{:else}
    <p>Loading...</p>
{/if}
## The JavaScript Event Loop
In SvelteKit, especially within load functions, you make asynchronous calls to fetch data. The event loop is the mechanism that allows JavaScript to handle these non-blocking operations. Understanding this helps you avoid race conditions and manage asynchronous tasks correctly. The key is to properly use async and await to ensure operations complete in the correct order.

Incorrect: Not awaiting a promise
Here, the load function might return before the user's preferences are fetched, leading to inconsistent UI.

TypeScript

// This is incorrect and can lead to bugs
export const load: PageServerLoad = async ({ cookies }) => {
    let preferences = { theme: 'light' };
    const userId = cookies.get('userId');

    if (userId) {
        // We "fire and forget" the promise, which is bad!
        db.getPreferences(userId).then(prefs => {
            preferences = prefs;
        });
    }

    // This return statement will likely execute BEFORE the promise resolves.
    return { preferences };
};
Better: Correctly awaiting promises
By using await, you ensure that the function pauses until the data is retrieved before it continues, guaranteeing that the correct data is returned.

TypeScript

export const load: PageServerLoad = async ({ cookies }) => {
    const userId = cookies.get('userId');

    if (userId) {
        // The function pauses here until the preferences are loaded
        const preferences = await db.getPreferences(userId);
        return { preferences };
    }

    // Return default preferences if no user
    return { preferences: { theme: 'light' } };
};
