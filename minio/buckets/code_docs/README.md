# MinIO Code Documentation Storage\n\n## Overview\n\nThis MinIO bucket stores processed code documentation and embeddings for the Code Ingestion Pipeline. It serves as the persistent storage layer for:\n\n- **Processed Code Chunks**: Segmented source code with metadata\n- **Embeddings**: 768-dimensional vectors from EmbeddingGemma\n- **Summaries**: S3+S4 hybrid legal and semantic summaries\n- **Metadata**: File relationships, timestamps, and processing history\n- **QLoRA Datasets**: Future fine-tuning datasets for legal AI models\n\n## Bucket Structure\n\n```\ncode_docs/\n├── chunks/\n│   ├── {file_hash}/\n│   │   ├── chunk_0.json\n│   │   ├── chunk_1.json\n│   │   └── ...\n│   └── ...\n├── embeddings/\n│   ├── {file_hash}/\n│   │   ├── chunk_0.bin\n│   │   ├── chunk_1.bin\n│   │   └── ...\n│   └── ...\n├── summaries/\n│   ├── {file_hash}/\n│   │   ├── chunk_0_summary.json\n│   │   ├── chunk_1_summary.json\n│   │   └── ...\n│   └── ...\n├── metadata/\n│   ├── files.json\n│   ├── processing_log.jsonl\n│   └── statistics.json\n└── qlora_datasets/\n    ├── legal_training_v1.parquet\n    ├── legal_validation_v1.parquet\n    └── legal_test_v1.parquet\n```\n\n## File Formats\n\n### Chunks (JSON)\n\n```json\n{\n  \"chunk_id\": \"abc123_chunk_0\",\n  \"file_path\": \"backend/services/embedding_service.py\",\n  \"file_hash\": \"abc123\",\n  \"chunk_index\": 0,\n  \"language\": \"python\",\n  \"content\": \"...\",\n  \"size_bytes\": 1024,\n  \"line_start\": 1,\n  \"line_end\": 50,\n  \"timestamp\": 1700000000000,\n  \"version\": 1\n}\n```\n\n### Embeddings (Binary)\n\n- Format: 32-bit float array (768 dimensions)\n- Size: 3,072 bytes per embedding (768 * 4 bytes)\n- Naming: `{chunk_id}.bin`\n- Metadata: Stored separately in JSON\n\n### Summaries (JSON)\n\n```json\n{\n  \"chunk_id\": \"abc123_chunk_0\",\n  \"summary_type\": \"hybrid\",\n  \"summary\": \"...\",\n  \"legal_compliance\": {\n    \"compliance_score\": 0.85,\n    \"risk_factors\": [...],\n    \"recommendations\": [...],\n    \"jurisdiction\": \"US\"\n  },\n  \"semantic_analysis\": {\n    \"key_concepts\": [...],\n    \"sentiment\": \"neutral\",\n    \"complexity_score\": 0.6,\n    \"topics\": [...]\n  },\n  \"processing_time_ms\": 245,\n  \"confidence\": 0.82,\n  \"timestamp\": 1700000000000\n}\n```\n\n### Metadata (JSON)\n\n#### files.json\n\n```json\n{\n  \"files\": [\n    {\n      \"file_path\": \"backend/services/embedding_service.py\",\n      \"file_hash\": \"abc123\",\n      \"language\": \"python\",\n      \"size_bytes\": 50000,\n      \"chunks_count\": 50,\n      \"embeddings_count\": 50,\n      \"summaries_count\": 50,\n      \"duplicates_count\": 2,\n      \"first_processed\": 1700000000000,\n      \"last_updated\": 1700000000000,\n      \"status\": \"processed\"\n    }\n  ],\n  \"total_files\": 1,\n  \"total_chunks\": 50,\n  \"total_embeddings\": 50,\n  \"last_updated\": 1700000000000\n}\n```\n\n#### processing_log.jsonl\n\nNewline-delimited JSON log of all processing events:\n\n```jsonl\n{\"timestamp\": 1700000000000, \"event\": \"file_added\", \"file_path\": \"...\", \"status\": \"success\"}\n{\"timestamp\": 1700000000100, \"event\": \"chunks_created\", \"file_path\": \"...\", \"count\": 50}\n{\"timestamp\": 1700000000200, \"event\": \"embeddings_generated\", \"file_path\": \"...\", \"count\": 50}\n```\n\n#### statistics.json\n\n```json\n{\n  \"total_files_processed\": 150,\n  \"total_chunks\": 7500,\n  \"total_embeddings\": 7350,\n  \"duplicate_rate\": 0.02,\n  \"average_chunk_size\": 1024,\n  \"average_processing_time_ms\": 245,\n  \"storage_used_bytes\": 22500000,\n  \"last_updated\": 1700000000000\n}\n```\n\n## QLoRA Dataset Format\n\nFuture fine-tuning datasets stored as Parquet files:\n\n### Columns\n\n- `instruction`: Legal task description\n- `input`: Code chunk or document excerpt\n- `output`: Expected legal analysis or summary\n- `embedding`: 768-dimensional vector (optional)\n- `metadata`: JSON with source file, chunk ID, etc.\n\n### Example\n\n```parquet\ninstruction: \"Analyze this code for legal compliance\"\ninput: \"def process_payment(amount): ...\"\noutput: \"This function handles payment processing and should include...\"\nembedding: [0.1, 0.2, ..., 0.3]  # 768 dimensions\nmetadata: {\"source\": \"backend/services/payment.py\", \"chunk_id\": \"xyz789_chunk_5\"}\n```\n\n## Access Patterns\n\n### Read Operations\n\n1. **Retrieve chunk by ID**\n   ```\n   GET /code_docs/chunks/{file_hash}/{chunk_id}.json\n   ```\n\n2. **Retrieve embedding**\n   ```\n   GET /code_docs/embeddings/{file_hash}/{chunk_id}.bin\n   ```\n\n3. **Retrieve summary**\n   ```\n   GET /code_docs/summaries/{file_hash}/{chunk_id}_summary.json\n   ```\n\n4. **List all files**\n   ```\n   GET /code_docs/metadata/files.json\n   ```\n\n### Write Operations\n\n1. **Store chunk**\n   ```\n   PUT /code_docs/chunks/{file_hash}/{chunk_id}.json\n   ```\n\n2. **Store embedding**\n   ```\n   PUT /code_docs/embeddings/{file_hash}/{chunk_id}.bin\n   ```\n\n3. **Store summary**\n   ```\n   PUT /code_docs/summaries/{file_hash}/{chunk_id}_summary.json\n   ```\n\n4. **Append to processing log**\n   ```\n   POST /code_docs/metadata/processing_log.jsonl\n   ```\n\n## Retention Policy\n\n- **Chunks**: Retained indefinitely\n- **Embeddings**: Retained indefinitely (768d vectors are small)\n- **Summaries**: Retained indefinitely\n- **Processing Logs**: Rotated monthly (keep 12 months)\n- **QLoRA Datasets**: Versioned, keep last 5 versions\n\n## Lifecycle Rules\n\n```xml\n<LifecycleConfiguration>\n  <Rule>\n    <ID>archive-old-logs</ID>\n    <Filter>\n      <Prefix>metadata/processing_log_</Prefix>\n    </Filter>\n    <Expiration>\n      <Days>365</Days>\n    </Expiration>\n  </Rule>\n  <Rule>\n    <ID>cleanup-temp-files</ID>\n    <Filter>\n      <Prefix>temp/</Prefix>\n    </Filter>\n    <Expiration>\n      <Days>7</Days>\n    </Expiration>\n  </Rule>\n</LifecycleConfiguration>\n```\n\n## Performance Considerations\n\n### Optimization Tips\n\n1. **Batch Operations**: Use multipart uploads for large files\n2. **Compression**: Store embeddings as compressed binary (gzip)\n3. **Partitioning**: Organize by file_hash for parallel access\n4. **Caching**: Use Redis for frequently accessed metadata\n5. **Versioning**: Enable object versioning for audit trail\n\n### Expected Metrics\n\n- **Chunk Size**: ~1-2 KB (JSON)\n- **Embedding Size**: ~3 KB (768 floats + metadata)\n- **Summary Size**: ~2-3 KB (JSON)\n- **Total per Chunk**: ~6-8 KB\n- **1000 Files × 50 Chunks**: ~300-400 MB\n\n## Integration with Pipeline\n\n### Upload Flow\n\n```\nCode Ingestion Pipeline\n    ↓\nGenerate Chunks → Store in MinIO (chunks/)\n    ↓\nGenerate Embeddings → Store in MinIO (embeddings/)\n    ↓\nGenerate Summaries → Store in MinIO (summaries/)\n    ↓\nUpdate Metadata → Store in MinIO (metadata/)\n    ↓\nQdrant Cache (R3) ← Embeddings + Metadata\n```\n\n### Download Flow\n\n```\nUI/API Request\n    ↓\nQuery Qdrant (R3 Cache)\n    ↓\nRetrieve from MinIO if needed\n    ↓\nReturn to Client\n```\n\n## Security\n\n- **Encryption**: Enable server-side encryption (SSE-S3)\n- **Access Control**: Use IAM policies for fine-grained access\n- **Versioning**: Enable for audit trail\n- **Lifecycle**: Automatic cleanup of old versions\n- **Backup**: Regular snapshots to external storage\n\n## Monitoring\n\n### Metrics to Track\n\n- Bucket size (GB)\n- Object count\n- Upload/download throughput\n- Error rates\n- Access patterns\n\n### CloudWatch Integration\n\n```yaml\nMetrics:\n  - BucketSizeBytes\n  - NumberOfObjects\n  - AllRequests\n  - 4xxErrors\n  - 5xxErrors\n```\n\n## Future Enhancements\n\n1. **Incremental Updates**: Only store changed chunks\n2. **Compression**: Gzip embeddings and summaries\n3. **Tiered
