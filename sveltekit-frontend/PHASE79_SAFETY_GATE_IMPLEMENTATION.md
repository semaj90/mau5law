# Phase 79: Safety Gate Implementation Guide

## Problem
LLM-generated fix suggestions sometimes include explanatory text instead of actual code. When these are written to source files, they corrupt them. Example:

```typescript
// ❌ BAD - This got written to flatbuffer-node-data.ts
The error summary indicates a problem within the __non_route__#internal file.
This file is typically generated by SvelteKit and handles internal logic.
The provided file content is empty, which is highly unusual...
```

## Solution
Phase 79 introduces a **Safety Gate** validation layer that prevents this by:

1. **Detecting content type** - Is this code or documentation?
2. **Validating syntax** - Does it have matching braces, quotes, etc.?
3. **Blocking problematic writes** - Refuse to write non-code to source files
4. **Providing rollback** - Restore previous file if write fails

## Architecture

### Core Validator (`phase79-safety-gate.mjs`)

```javascript
// Detect if content is code or documentation
const { type, confidence } = detectContentType(content);
// Returns: { type: 'code' | 'documentation', confidence: 0-1 }

// Validate syntax
const validation = validateFileContent(content, filePath);
// Returns: { canWrite: boolean, issues: string[], confidence: 0-1 }

// Safe write with validation
const result = await safeWriteFile(filePath, content);
// Returns: { success: boolean, backupPath?, error? }
```

### Integration Layer (`phase79-integration.mjs`)

Wraps existing pipelines:

```javascript
// Wrap any fix function
const safeFix = validateBeforeWrite(existingFixFunction);
await safeFix();  // Now validates before writing

// Batch validate patches
const validation = await batchValidatePatches(patches);
const results = await safeBatchApply(patches, { stopOnError: true });
```

## Validation Rules

### Content Type Detection
Scores code vs. documentation indicators:

**Code Indicators** (higher score = more likely code):
- Keywords: `import`, `export`, `const`, `function`, `if`, `return`, etc.
- Syntax: `{`, `}`, `=>`, `()`, `;`
- Comments: `//`, `/*`

**Documentation Indicators** (higher score = more likely documentation):
- English prose: "The", "This", "However", "which"
- Markdown: `#`, ``` ``` ```
- Sentence endings: `.`
- Bullet points: `-`

### Syntax Validation

**TypeScript/JavaScript** (`.ts`, `.js`, `.mts`, `.mjs`):
- Balanced braces `{}`, brackets `[]`, parentheses `()`
- Terminated strings and template literals
- No double semicolons or commas
- Valid identifier names

**Svelte** (`.svelte`):
- Balanced `<script>` tags
- Balanced `<style>` tags
- Proper directive usage

### File Write Safety
- Creates backup before writing
- Validates content first
- Rolls back on error
- Never overwrites without validation

## Usage Examples

### Example 1: Prevent Documentation Corruption
```javascript
const badContent = `The error indicates a problem...`; // From LLM
const validation = validateFileContent(badContent, 'test.ts');
console.log(validation.canWrite); // false
console.log(validation.issues);   // ["Content detected as documentation"]
```

### Example 2: Safe Patching
```javascript
const patch = {
  filePath: 'src/components/Button.svelte',
  content: `<script>...</script>...`  // Valid code
};

const result = await safeWriteFile(patch.filePath, patch.content);
if (result.success) {
  console.log(`✅ Written: ${result.bytesWritten} bytes`);
} else {
  console.log(`❌ Failed: ${result.error}`);
}
```

### Example 3: Wrapping Existing Fixers
```javascript
// Original fixer (might write bad content)
async function myFixer(error) {
  const fix = await llm.generate(prompt);
  fs.writeFileSync(file, fix);
}

// Wrap with validation
const safeMyFixer = validateBeforeWrite(myFixer);

// Now it validates before writing
const result = await safeMyFixer(error);
if (result.blocked) {
  console.log('Write blocked due to validation failure');
}
```

```javascript
import { validateBeforeWrite } from './phase79-integration.mjs';

const safeApplyFix = validateBeforeWrite(applyPatchFromACE);
```

### For Phase 76 (ACE Agent)
```javascript
import { safeBatchApply } from './phase79-integration.mjs';

// Before applying patches
const result = await safeBatchApply(generatedPatches, {
  stopOnError: true,
  dryRun: false
});
```

### For Custom Fixers
```javascript
import { safeWriteFile, validateFileContent } from './phase79-safety-gate.mjs';

// Validate first
const validation = validateFileContent(content, filePath);
if (!validation.canWrite) {
  throw new Error(`Cannot write: ${validation.issues.join(', ')}`);
}

// Then write
const result = await safeWriteFile(filePath, content, {
  backup: true,
  validate: false  // Already validated above
});
```

## Configuration

No configuration needed - validation is automatic and always-on for:
- Content type detection
- Syntax validation
- File write safety

Override with `--force` flag if absolutely necessary:
```javascript
// Force write even if validation fails
await safeWriteFile(filePath, content, { force: true });
```

## Performance Impact

- **Detection**: ~1ms per file (regex-based)
- **Syntax validation**: ~2-5ms per file (pattern matching)
- **File I/O**: Standard fs operations
- **Backup creation**: ~5-10ms per file

Negligible impact on overall pipeline performance.
